# Отдельный аппаратно-ускоренный режим Windows

Для тяжёлых IDE предусмотрен отдельный аппаратный режим WHPX.

## Пользовательский запуск

- `run-linux.bat` — программный TCG, автоматически от 320 МиБ / до 2 CPU,
  без настройки гипервизора.
- `run-linux-accelerated.bat` — явный WHPX. Оба открывают тот же `linux.img.vtoy`,
  используют общий `.launch.lock`, постоянный `.uefi-vars.fd` и LOCAL RTC.
- На подготовленной Windows запуск WHPX выполняется обычным пользователем.
  `enable-acceleration.bat` — отдельная первоначальная настройка с UAC при
  необходимости. Она включает HypervisorPlatform и hypervisorlaunchtype=auto,
  сообщает о необходимости перезагрузки; автоматической перезагрузки нет.
- В BIOS/UEFI нужна включённая AMD-V/SVM или Intel VT-x. Проверка обычного старта
  читает WHvGetCapability, поэтому не требует административного DISM-запроса.

TCG и WHPX подключают системный диск по тому же фиксированному PCI-адресу, что
и сборщик, с первым приоритетом загрузки. Смена режима не пересоздаёт UEFI VARS.

Наличие готового WHPX API определяется непосредственно, а не только состоянием
optional feature: уже работающий Hyper-V также может предоставлять нужный API.

## Ресурсы и диагностика

TCG и WHPX выбирают максимальный целый МиБ в бюджете:

```text
RAM Linux = min(текущая свободная RAM, вся физическая RAM) - 2048 МиБ
```

Минимум Linux — 320 МиБ. Прежние caps 4/6 ГиБ, половина total RAM и округление
до целого ГиБ сняты. Например, free 2429 МиБ даёт 381 МиБ гостю, free 3030 —
982 МиБ, free 10000 — 7952 МиБ. Резерв 2048 МиБ не расходуется на guest RAM;
он оставляет запас для Windows и собственных выделений QEMU.

Auto CPU WHPX: до четырёх, не более половины логических CPU, минимум один;
TCG — до двух. В обоих режимах `-RamMb 0 -Cores 0` означает авто-подбор.
Параметры можно передать без редактирования BAT; значения пользователя не
дублируются скрытыми defaults:

```bat
run-linux.bat -RamMb 512 -Cores 1
run-linux-accelerated.bat -RamMb 4096 -Cores 2
run-linux-accelerated.bat -RamMb 6144 -Cores 4
```

Для минимальных 320 МиБ Linux нужно не менее 2368 МиБ **свободной RAM** перед
стартом, включая резерв. Явный запрос большей памяти не уменьшается автоматически:
выберите меньший профиль или верните `-RamMb 0`. 320 МиБ — экспериментальная граница
базового сеанса с редактором, не комфортный профиль всех учебных приложений.

`run-from-usb.bat` — общий вход к `run-from-usb.ps1`: запуск PowerShell 5.1,
передача аргументов, код выхода и показ ранних ошибок. `run-linux*.bat` задают
путь/формат общего Linux-образа, RTC и ускоритель; без общего BAT они не работают.

В командной строке ровно один `-accel whpx,kernel-irqchip=off`, CPU Westmere;
TCG fallback не добавляется. `-accel help` проверяет поддержку в выбранном QEMU.
Если API/backend недоступен, сохраняется ошибка с инструкцией настройки.
Логи в каталоге `logs` комплекта, выбранный режим — поле Accel в
launch-profile.json, API — whpx-status.json, ошибки QEMU — qemu-stderr.log.
Поля RamSelection, RamBudgetMb, MinimumRamMb и WindowsReserveMb объясняют,
почему выбран конкретный объём.

Экран `UEFI Interactive Shell` / `Shell>` означает, что Linux ещё не загрузился.
После закрытия такого сеанса ошибка сохраняется как этап `uefi-boot`; сохраните
журналы для диагностики. Удалять образ или постоянный VARS для этого не нужно.

Ускоряется исполнение CPU. Профиль оставляет стабильный 2D VGA 1024x768/60,
GTK gl=off. Дисковая производительность носителя измеряется отдельно.

Оба режима сохраняют изменения в одном образе. Между переключениями штатно
выключайте Linux. При нехватке памяти запускатель сообщает требуемый резерв;
не уменьшайте его вручную для обхода проверки.
