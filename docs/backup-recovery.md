# Резервное копирование и восстановление Linux-комплекта

`backup-system.bat` создаёт ZIP64-копию остановленного файлового комплекта:

- весь `linux.img.vtoy`, включая проекты, настройки, Linux-права и базы данных;
- постоянный `linux.img.vtoy.uefi-vars.fd`;
- QEMU, библиотеки, запускатели и памятки;
- каталоги `ventoy` и `examples`, если они присутствуют.

Программы работают обычным Windows-пользователем, без UAC. Архив сжимается потоково;
SHA256 каждого файла вычисляется при копировании, затем весь архив распаковывается
потоково для независимой проверки. Рядом сохраняется SHA256 самого ZIP.

## Создание копии

1. Штатно выключите Linux и дождитесь закрытия QEMU.
2. Создайте каталог для копий на диске компьютера, например `E:\LinuxFlashcard-backups`.
3. Запустите `backup-system.bat` рядом с Linux и укажите новый путь `.zip`.
4. Дождитесь сообщения о создании **и полной проверке** копии.

До начала требуется свободное место не меньше несжатого комплекта — обычно
около 27 ГиБ. Итоговый ZIP часто существенно меньше, но степень сжатия зависит
от пользовательских данных. Для больших архивов нужен NTFS/exFAT, не FAT32.

Из исходников команда выглядит так:

```powershell
win\backup-system.ps1 -Root V:\ -Archive E:\LinuxFlashcard-backups\school.zip
```

На время операции удерживаются тот же `.launch.lock`, что у запускателя, и
read-only handles образа/VARS. Занятый записывающим процессом образ не копируется.
Готовая копия не перезаписывается; после прерывания остаётся `.partial`, который
не считается завершённым архивом. Для повторной попытки используйте новое имя.

## Проверка существующей копии

```powershell
win\backup-system.ps1 -Action Verify -Archive E:\LinuxFlashcard-backups\school.zip
```

Проверяются SHA256 ZIP при наличии sidecar, manifest, точные длины и SHA256 всех
записей. Неизвестные, дублирующиеся и небезопасные пути отвергаются.

## Восстановление и пробный запуск

Запустите `restore-system.bat` и укажите архив и **новый, ещё не существующий**
каталог. Либо выполните:

```powershell
win\backup-system.ps1 -Action Restore `
  -Archive E:\LinuxFlashcard-backups\school.zip `
  -Destination E:\LinuxFlashcard-restored
```

Сначала проверяется весь архив. Затем файлы распаковываются в новый staging-каталог,
читаются обратно и сверяются с SHA256. Только полностью проверенный комплект
публикуется под именем назначения. Существующие файлы и каталоги не заменяются.
`restore-result.json` фиксирует завершение операции.

Из восстановленного каталога можно запускать `run-linux.bat` или
`run-linux-accelerated.bat`. Проверяйте нужный проект/документ и штатное выключение.

Каталог восстановления может содержать кириллицу, пробелы и квадратные скобки.
Запускатель сохраняет исходный путь в журнале, а файловым backend QEMU передаёт
совместимые относительные ASCII-пути. При необходимости используются короткие
имена или временные NTFS hard links без копирования большого образа; собственные
временные ссылки удаляются после завершения QEMU.

Это резервная копия файлового Linux-комплекта. Разметка USB и раздел Ventoy EFI
подготавливаются через `build-all.bat`; инструмент восстановления не форматирует
физические диски. Личные файлы на Windows-томе вне образа и комплекта запуска следует
копировать дополнительно. Перенос проверенной восстановленной системы на уже
используемую физическую USB — отдельная операция с сохранением её текущего состояния.

## Обновление программ и откат

Перед обновлением ПО создайте свежую проверенную копию. Обновления Debian и
инструментов выполняются внутри существующей системы, чтобы сохранять проекты,
настройки и базы данных. Заводской `build-all -NewBuild` создаёт новую систему.
Для проверки отката восстановите предыдущую копию в новый каталог и проверьте
рабочий сценарий из неё. Автоматическое обновление/слияние пользовательских систем
этим инструментом не выполняется.
