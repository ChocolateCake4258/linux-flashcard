# Сохранённый конвейер LinuxFlashcard

Комплект закрепляет рабочую заводскую основу Debian/XFCE, набор и версии программ,
исходники сборщика, portable Python, QEMU и все дополнительные входные файлы.
Заводская основа взята из проверенного результата фабрики перед первым входом.
При запуске создаётся новая сборка с собственным ID, повторными функциональными
проверками и проверкой direct → Ventoy → direct.

## Доступность комплекта

Автономный архив `linux-flashcard-pipeline-<версия>.zip` — отдельный комплект
с подготовленной Linux-системой и закреплёнными компонентами для повторной
сборки без скачивания пакетов.

На 11 ноября 2026 года в [релизе RC10](https://github.com/ChocolateCake4258/linux-flashcard/releases/tag/v2026.10.25-rc10)
этот архив не опубликован. Доступный `*-windows.zip` подготавливает систему
с первоначальным скачиванием компонентов; инструкция приведена в
[README, раздел «Скачивание»](https://github.com/ChocolateCake4258/linux-flashcard/blob/main/README.md#скачивание).

Следующие разделы описывают использование уже подготовленного автономного
комплекта. Кнопка `REBUILD.bat` входит в такой комплект.

## Запуск готового автономного комплекта

Для запуска нужны Windows x64 с Windows PowerShell 5.1 и права администратора
для подготовки образов. Проверенная среда и требования к памяти описаны в
[README, раздел «Требования»](https://github.com/ChocolateCake4258/linux-flashcard/blob/main/README.md#требования).

1. Полностью распакуйте `linux-flashcard-pipeline-<версия>.zip` на локальный
   NTFS-диск. Для 32-ГБ образа оставьте дополнительно около 70 ГБ свободного места.
2. Откройте **`REBUILD.bat`** и подтвердите UAC.
3. Дождитесь окончания. Путь рабочего каталога показан в окне; готовый файл —
   `artifacts/linux-flashcard-usb.img`, рядом находятся SHA256 и build-result.json.

Флешка для получения файла-образа не требуется. Повторный REBUILD продолжает
сохранённую сборку. Для отдельной новой сборки:

```bat
REBUILD.bat -NewBuild
REBUILD.bat -Status
REBUILD.bat -Plan
```

`CHECK.bat` позволяет отдельно проверить размеры и SHA256 файлов комплекта
и комплектность исходников. При запуске `REBUILD.bat` и `START.bat` проверка
комплекта также выполняется автоматически.
`START.bat` выполняет обычный выбор USB, подтверждение стирания, сборку и полную
проверку записи, когда появится подходящий носитель. Размер внешнего образа
рассчитывается по выбранной USB; внутренняя Linux-система остаётся 26 ГиБ.

## Что закреплено

- `source`: исполняемая копия конвейера и её `RELEASE-MANIFEST.json`;
- `inputs`: подготовленная заводская QCOW2-основа, portable Python, пакеты QEMU
  и его библиотек, Ventoy/vtoyboot и установочные файлы дополнительных программ;
- `PACKAGES.tsv`: точные версии системных пакетов Debian/Microsoft в заводской основе;
- `REFERENCE.json`: происхождение основы, контрольные суммы и идентификаторы Docker-образов;
- `PIPELINE-MANIFEST.json`: размеры и SHA256 файлов всего комплекта.

В корне находятся `CHECK.bat`, `REBUILD.bat`, `START.bat` и `ИНСТРУКЦИЯ.md`.
В качестве инструкции упаковщик включает копию этого документа.

Восстановление из этого комплекта автономно: входы берутся из `inputs`, пакеты и
контейнеры уже находятся в заводской основе. Host downloader запрещает обращения
в сеть; заводские VM получают ограниченную сеть. Отсутствующий или изменённый
вход останавливает сборку с ошибкой вместо подбора новой версии.

Первый пароль задаётся при первом пользовательском запуске. Рабочий стол выпуска
свободен от текстовых листов с проверочными инструкциями. Программы, учебные примеры
и команды диагностики доступны в системе.

Рабочие файлы, TEMP/кэш и логи создаются в `work-<версия>` рядом с распакованным
конвейером, на том же диске. Каталог отдельный для каждой версии конвейера.

Это воспроизведение набора программ и заводских настроек. Служебные ID сборок,
временные метки и результаты повторных проверок формируются заново; SHA нового
полного образа может отличаться. Личный пароль и проекты создаются владельцем
в полученной системе.

## Подготовка комплекта

Упаковщик `tools/make-pipeline-capsule.py` из исходников проекта формирует архив
из проверенного кэша компонентов и чистой подготовленной QCOW2-основы до первого
пользовательского входа. Рядом с основой требуются `template.json` с её описанием
и контрольными суммами и `packages.tsv` с версиями установленных пакетов.

Эта инструкция описывает запуск готового архива. Подготовка и экспорт чистой
основы требуют отдельной процедуры; полный порядок экспорта здесь пока не описан.
