# Флешка «два тома, одна система»

Главный результат способа B (`win\build-all.bat`) — флешка с **одной системой** и
двумя способами её запуска: нативным и через QEMU. Никаких копий системы не делается.

## Разметка флешки (GPT)

```
┌────────────────────────────────────────────────────────────┐
│ P0  1 МБ  bios-boot        — нативная загрузка Legacy BIOS │
├────────────────────────────────────────────────────────────┤
│ P1  2 GiB FAT32 «FLASHCARD» (она же ESP, /boot/efi)        │
│     ▸ qemu/            portable QEMU (без установки)       │
│     ▸ run-qemu.bat     кнопка «запустить систему в QEMU»   │
│     ▸ README.txt, docs/                                    │
│ У Windows это «съёмный диск» с буквой → пополнить можно    │
├────────────────────────────────────────────────────────────┤
│ P2  остаток ext4 «/»      ЕДИНСТВЕННАЯ система             │
│     ▸ Kubuntu + всё ПО    нативный запуск = её же           │
│                           QEMU-кнопка   = её же             │
└────────────────────────────────────────────────────────────┘
```

Для будущих заводских образов диск остаётся 28 GiB (`DiskSizeGb=28`) для
совместимости с обычными флешками на 32 GB: ESP 2 GiB, P2 ~26 GiB.
У отдельной подтверждённой флешки размером 31042043904 байт после изменения
разметки P2 ~26.9 GiB, включая хвост носителя за пределами 28 GiB.
Существующие `.img`/`.qcow2` и исторические тесты/резервные документы не меняются.

- **Нативная загрузка**: ПК грузится с флешки через boot-меню (UEFI — тома P1,
  Legacy BIOS — P0). GRUB поднимает систему с P2.
- **QEMU-кнопка**: `run-qemu.bat` на P1 открывает **флешку целиком**
  (`\\.\PhysicalDriveN`), GRUB внутри образа сам поднимает тот же P2.
  Данные общие — что изменится в QEMU, при нативной загрузке останется (и наоборот).

## Ключевое ограничение QEMU-кнопки

Windows разрешает обычному процессу читать **только файлы**, а физический диск —
только администратору. Поэтому:

| ПК | Нативная загрузка | QEMU-кнопка (`run-qemu.bat`) |
|---|---|---|
| Свой/свободный (есть admin) | ✅ | ✅ (UAC один раз) |
| Учебный, нет admin, boot-меню доступно | ✅ | ❌ (UAC закрыт) |
| Учебный, нет admin и boot-меню закрыто | ❌ | ❌ → нужен файловый режим `run-from-usb` (см. ниже) |

Три условия «нет прав + закрыто boot-меню + одна система **без копий**»
несовместимы физически: без прав Windows не даст QEMU прочитать раздел.
В этом наборе ограничений выбираются два из трёх.

## Файловый режим (компромиссный)

`win\run-from-usb.bat` запускает систему из **файла-образа** (qcow2/raw), который
лежит рядом с `win\`. Он работает **без прав** и без boot-меню, но означает
**копию** системы на обычной FAT-флешке. Он не является частью флешки «два тома»
и нужен только там, где свободны и `run-qemu.bat`, и нативная загрузка.

## Клонирование флешки

После сборки на ПК остаются:

- `virtual-disk.img` (~28 ГБ, вместе с `virtual-disk.img.sha256`) — записывается
  через `win\write-image.bat` на другой USB (нужны права);
- `virtual-disk.qcow2` — меньший по размеру; подходит для файлового режима
  `run-from-usb` и как исходник конвертации.

Новая флешка «два тома» получается только записью **raw** + последующей докладкой
`qemu/` и содержимого `win\usb-launcher\` на том P1 (это делает стадия 9
`build-all.ps1` или вручную по инструкции ниже).

## Перенос вручную (без пересборки)

1. `win\write-image.bat` → выбрать raw-образ и флешку (права администратора).
2. После записи том P1 появится как диск с меткой `FLASHCARD`.
3. Скопировать на P1:
   - `win\..\qemu\`      → `P1:\qemu\`
   - `win\usb-launcher\*` → `P1:\` (run-qemu.bat, run-qemu.ps1, lib\)
   - `docs\`              → `P1:\docs\`
4. Безопасно отключить P1 (иконка в трее).

## Примечания

- **Secure Boot**: нативная загрузка — как в курсовой; подписанный shim
  устанавливается, но при конфликте прошивки отключите Secure Boot либо
  используйте QEMU-кнопку. Fallback-путь `\EFI\BOOT\BOOTX64.EFI` пишется при
  установке (unlike NVRAM-запись он работает и в QEMU, и на любом ПК).
- **Старая разметка с ESP 7 GiB**: редкие старые UEFI спотыкаются об ESP >2 GiB —
  тогда используйте QEMU-кнопку или Legacy BIOS. В новых сборках ESP 2 GiB.
- **GRUB**: ставится с virtio-модулями (установка в QEMU) и стандартными
  USB/SATA/ahci — нативный запуск с флешки и QEMU покрыты одиним набором.
- **Конфликт блокировок**: перед `run-qemu.bat` закройте программы, которые
  держат том P1 открытым (проводник с флешкой и т.п.). Полностью отключать том
  P1 не нужно — иначе кнопка не определит, какая это флешка.
- Память VM: `Get-PfRecommendedRamGb` = max(4, RAM/3, 12); ускемый фактор —
  WHPX; при его отсутствии QEMU сам перейдёт на TCG.
