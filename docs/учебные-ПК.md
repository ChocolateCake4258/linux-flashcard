# Работа на учебных ПК

Сценарии использования флешки с учётом типичных ограничений учебных машин:
нет прав администратора, отключена виртуализация (WHPX/Hyper-V), закрыто меню
загрузки, включён Secure Boot, запрет на запуск программ с флешки.

Основная флешка — **«два тома, одна система»** (`win\build-all.bat`): одна
копия системы, два способа запуска. Схема и ограничения — в
[`docs/два-тома.md`](два-тома.md).

## Уровень «всё разрешено» (свой компьютер, свободный класс)

1. **Нативная загрузка** — выбрать флешку в boot-меню (UEFI/BIOS).
   Secure Boot можно не отключать: ставится подписанный shim; при конфликте
   прошивки — отключить Secure Boot или использовать п. 2.
2. **`run-qemu.bat`** на томе P1 флешки — запуск этой же системы в QEMU.
   Требует прав администратора (UAC запрашивается автоматически). Данные
   общие с нативной загрузкой — копий не создаётся.

## Уровень «учебный ПК, нет прав администратора»

- **Нативная загрузка работает**, если доступно boot-меню (F12/F2/ESC и т.п.).
  Это рекомендуемый путь: прав не нужно, скорость нативной.
- **`run-qemu.bat` недоступен**: Windows не даёт обычному процессу открывать
  физический диск (`\\.\PhysicalDriveN` — только администратор). Кнопка
  честно объяснит ситуацию и предложит нативную загрузку.

## Уровень «закрыто всё» (нет прав + boot-меню + Secure Boot)

Единственный полностью «бесправный» режим — **файловый** `win\run-from-usb.bat`.
Это **копия системы** в виде файла-образа (qcow2/raw) на обычной FAT-флешке.
Он не входит в конструкцию «два тома» и готовится отдельно:

1. после способа B сохраните `virtual-disk.qcow2`;
2. скопируйте его на любую FAT-флешку рядом с `win\`;
3. на учебном ПК: `win\run-from-usb.bat` (без прав, WHPX не нужен — TCG).

Три условия «нет прав + закрыто boot-меню + одна система без копий»
несовместимы: без прав Windows не позволит прочитать раздел P2. Выбираются
два из трёх.

## Почему бывает медленно, и что с этим делать

| Причина | Признак | Решение |
|---|---|---|
| Нет WHPX/Hyper-V (нет прав включить) | QEMU идёт на TCG, система «тормозит» | это штатный режим; снизить RAM/ядра (`-RamMb`, `-Cores`) |
| ПК слабый (2–4 ГБ ОЗУ) | нехватка памяти у хоста | запускать ВМ с меньшим RAM |
| Обычный медленный USB 2.0 | долгая загрузка | использовать USB 3.x-порт |

## Что делать дома (до учебного ПК)

```sh
win\build-all.bat          # собрать флешку «два тома» (стадии 0–9, один клик)
```

После сборки остаются `virtual-disk.img`/`.qcow2` — для клонирования флешки
и/или файлового режима. Запись второй флешки «два тома» — `write-image.bat`
+ докладка на P1 см. [`два-тома.md`](два-тома.md) («Перенос вручную»).

## Чек-лист переносимости

- [ ] Нативная загрузка работает на своём ПК (уровень «всё разрешено»)
- [ ] `run-qemu.bat` поднимает ту же систему (проверка UAC)
- [ ] На учебном ПК без прав нативная загрузка работает (если есть boot-меню)
- [ ] (резерв) `run-from-usb.bat` работает из файла-образа
- [ ] Данные, созданные в QEMU, видны при нативной загрузке и наоборот
