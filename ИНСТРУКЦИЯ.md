# Подготовка Linux-флешки

## 1. Скачивание, распаковка и проверка

Скачайте **[Windows-пакет linux-flashcard-2026.11.11-rc11-windows.zip](https://github.com/ChocolateCake4258/linux-flashcard/releases/download/v2026.11.11-rc11/linux-flashcard-2026.11.11-rc11-windows.zip)**
из [релиза 2026.11.11-rc11](https://github.com/ChocolateCake4258/linux-flashcard/releases/tag/v2026.11.11-rc11).
Это предварительный выпуск Debian 13/XFCE.

Полностью распакуйте Windows ZIP на локальный NTFS-диск. Для подготовки 32-ГБ
флешки рекомендуется около 70 ГБ свободного места.

Запустите `CHECK.bat` и дождитесь успешной проверки. Он автоматически сверяет
размеры и SHA256 файлов с `RELEASE-MANIFEST.json`; ручная сверка хешей не нужна.
Проверка не скачивает ОС и не выбирает физический носитель.

`RELEASE-MANIFEST.json` включён в пользовательский Windows-пакет. Автоматические
архивы GitHub **Source code** и **Code → Download ZIP** содержат исходники без
этого файла, необходимого для `CHECK.bat`.

## 2. Автоматическая подготовка

Подключите тестовую USB от 32 ГБ и откройте `START.bat`. Выберите номер в
квадратных скобках, сверяя модель и serial. Ввод `yes` разрешает стереть выбранный
носитель после сборки. Подтвердите UAC и оставьте окно открытым до результата.

Скрипт скачает и проверит входные файлы, подготовит Debian/XFCE и учебные программы,
проверит приложения и общие данные через direct → Ventoy → direct, затем запишет USB
и проверит её чтением. QEMU и кнопки запуска уже включены в образ.

## 3. Продолжение и новая сборка

Повторный `START.bat` подхватывает сохранённую сборку. Подключите тот же USB.
Если сохранённая сборка относится к другой версии исходников, новый пакет создаст
отдельный workspace. `-Rewrite` повторяет совместимый образ, а не обновляет его
содержимое до новой версии. `-Workspace` другой версии отвергается до записи.
Если запись была прервана, она начнётся заново из проверенного образа.
Готовая USB повторно не стирается без `-Rewrite`.

Проверенные промежуточные файлы удаляются автоматически после завершения следующего
этапа. Состояние, ISO, кэш и готовый образ сохраняются. Для обновления исходников
после assembly начинайте новую сборку; прежний snapshot остаётся фиксированным.

```bat
START.bat -Status
START.bat -NewBuild
START.bat -Rewrite
START.bat -Workspace E:\LinuxFlashcard-new
```

Для полного выпуска только файла-образа используйте `BUILD-IMAGE.bat`.
Он проходит те же проверки Linux, но не открывает физический USB на запись.

## 4. Первый вход

После подготовки безопасно извлеките USB. Для запуска из Windows откройте
`run-linux.bat` или `run-linux-accelerated.bat` с самой флешки. При первом старте
задайте пароль для student на локальном экране Linux; затем откроется LightDM.
Для нативного режима выберите USB в UEFI boot-меню совместимого ПК.

В обоих режимах используется одна система. Создайте тестовый документ, штатно
выключите Linux и проверьте документ после повторного запуска и смены режима.

### Если на учебном ПК мало памяти

Обе кнопки автоматически берут максимум текущей свободной RAM за вычетом
2048 МиБ резерва Windows/QEMU. Округления до целого ГиБ и лимитов 4/6 ГиБ нет:
используется каждый доступный целый МиБ. Нижняя граница Linux — 320 МиБ.
TCG выбирает до 2 CPU, WHPX — до 4 CPU, не более половины логических CPU.
Можно явно задать меньший объём; откройте терминал в каталоге готовой флешки:

```bat
run-linux.bat -RamMb 512 -Cores 1
```

В PowerShell перед именем BAT добавьте `./` или `.\`. Значение `-RamMb 0`
означает авто-подбор. Явный `-RamMb 320` задаёт предельный проверенный профиль;
значения ниже 320 отклоняются. Для автоматического запуска нужно хотя бы
2368 МиБ свободной RAM: 320 для Linux и 2048 резерва.

| Свободно перед стартом, МиБ | Автоматически для Linux, МиБ |
|---:|---:|
| 2368 | 320 |
| 2429 | 381 |
| 3030 | 982 |
| 5000 | 2952 |
| 10000 | 7952 |

320 МиБ подтверждены только для базового сеанса XFCE с редактором; тяжёлые IDE,
браузер и несколько серверов требуют больше памяти. Сам QEMU также расходует
память сверх параметра гостя. Общая установленная RAM не равна текущей свободной.

В пакетах до RC9 `run-linux.bat` сам добавлял `-RamMb 4096 -Cores 2`, поэтому
правильно введённые пользовательские параметры ошибочно получались дважды.
Для такого старого комплекта доступен прямой общий вход без дублирования:

```bat
run-from-usb.bat -DiskPath ".\linux.img.vtoy" -DiskFormat raw -RtcBase localtime -RamMb 2048 -Cores 1
```

`run-from-usb.bat` — служебная оболочка, которая запускает `run-from-usb.ps1`,
передаёт параметры, сохраняет код выхода и показывает раннюю ошибку. Настройки
именно готового RAW-образа задают `run-linux.bat` и `run-linux-accelerated.bat`;
общий BAT не следует удалять. Логи и фактические ресурсы — в `logs` комплекта.

## 5. Где находятся данные

- рядом с распакованным проектом: `LinuxFlashcard-work` — сборки, загрузки, кэши;
- в workspace: `factory-state.json`, `jobs`, `artifacts` — состояние, логи и образы;
- на USB: `linux.img.vtoy` — система/проекты, `.uefi-vars.fd` — постоянная прошивка;
- на USB: `logs` — журналы обычного запуска.

Выбор диска сборки явный: по умолчанию диск распакованного проекта. Другой каталог
задаётся через `-Workspace`. Системный диск не выбирается автоматически.
